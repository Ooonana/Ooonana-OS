## Installer dependency repair

Real VM preparation exposed missing `lsblk`; the installer subsequently exposed
missing `blkid` after formatting. The supported upstream splits these tools,
`findmnt`, `losetup`, `mount` and `umount` into individual packages; importing
`util-linux` and `util-linux-misc` did not provide them. The [upstream package split](https://raw.githubusercontent.com/alpinelinux/aports/3.24-stable/main/util-linux/APKBUILD)
also explains the distinction. Both desktop profiles and
native core runtime dependencies now request the actual packages. The package factory
imports all native-core prerequisites even with a custom empty desktop profile.
The runtime audit now checks these tools, partitioning, filesystem formatters
and `rsync` before an image can be accepted.

Installer target preparation requires `lsblk` before discovering a target, then
checks all selected filesystem/swap/loop helpers before disk writes. Missing
inventory cannot silently bypass mounted-descendant checks. Negative tests prove
missing `lsblk`, `blkid`, `losetup` or `mkswap` stops before unsafe progress.
Dry-run behavior is retained.

The unpublished stage receives six new disk-tool packages and rebuilt
native core. Tested musl, PAM, i3, locker and Qt packages stay pinned. Session
provider imports are an isolated experiment, not accepted release dependencies.
`lsblk` and `findmnt` 2.42.3 execute against the old candidate libraries in the
owned source image after an actual signature-verified Ooonana installation.

Final signature-verified private upgrade passes in
`/var/tmp/ooonana-tools-upgrade-20261031.LSuCY6PD`. All six installed ELF hashes
match their actual archives and execute with the pinned candidate libraries.
The installer matches checkout bytes; the custom boot script remains byte-for-byte
unchanged and its pending factory default matches the rebuilt core archive.
PAM helper mode remains 4755. The first fixture used an unmodified factory boot
script and correctly received the new default; expecting it to remain old was a
fixture error, not a configuration-preservation failure.

Installed boot also lacked a step for configured fstab mounts. The new factory
boot script mounts local configured filesystems before memory/services/login,
skips `_netdev` entries and uses a bounded command. Failure writes a transient
native PAM nologin guard and stops startup; existing administrator nologin policy is
preserved. A missing configured home cannot silently become a fresh empty home.
Live boot does not run this installed-only operation. Native mount tools survive
the builder's BusyBox link restoration. Six isolated behavioral checks pass.
Existing customized boot scripts are preserved and receive a pending factory
default; this does not silently replace their policy during upgrade.
Custom authentication still requires its separately listed acceptance checks.

Actual native PAM/getty VM rejection also passes:
`/var/tmp/ooonana-storage-login-20261101.ut8Db6vD`.
Correct credentials cannot enter the desktop while the transient guard exists.
The initial minimal fixture omitted full rcS's `/var/run -> /run` alias; vendor
